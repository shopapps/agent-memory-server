Working Memory

Long-term memory graph

A short-term workbench for recent project chat. Keep up to 30 exchanges for seven days. Only selected project facts move into the long-term graph.

The installer creates a local user ID to find your recent chats across Codex and Claude. It is a label, not a password or access check. Local installs fill it in from saved settings when available. Otherwise, use the installer's review link or copy userId from ams-working-memory.json in your ~/.codex or ~/.claude folder (inside the project for project installs). The links between this page and the graph keep this ID.

The API token lets this page read and change memories when your Agent Memory server requires an access token. Leave it blank for the default local setup. It is not your OpenAI API key. This page does not save it or put it in links.

Check that saving and recall work

In an agent task, say: “For this test project, our agreed example customer is Copper Finch. Confirm this, but do not save it with memory tools—we are testing automatic capture.”

Find that session below. A chat message alone is not a saved fact. Wait for Saved to long-term, or approve the suggestion if you use review mode. Then open a new task in the same project and ask: “Search long-term shared memory for our example customer. Give me the name and memory ID. Do not answer from chat alone.”

The returned ID should match the saved fact below. No suggestion can also be a valid result: the AI is selective. Delete the disposable test fact from the graph when finished. This page refreshes every ten seconds while visible.
